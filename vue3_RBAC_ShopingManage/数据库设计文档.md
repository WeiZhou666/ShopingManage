# 数据库设计文档

> `vue3_RBAC_ShopingManage` 后台管理系统的后端数据库设计方案。
> 数据库选型：**MySQL 8.0+**（支持 JSON、窗口函数、CTE）
> 字符集：`utf8mb4`，排序规则：`utf8mb4_unicode_ci`

---

## 一、模块概览

| 模块 | 涉及表 | 说明 |
|---|---|---|
| 用户管理 | users, user_addresses, operation_logs | C 端消费者 |
| 商品管理 | categories, products, product_skus | 商品 + 规格 |
| 订单管理 | orders, order_items, order_logs | 订单主表 + 商品明细 + 操作日志 |
| 物流管理 | logistics_companies, shipment_records | 物流公司 + 发货记录 |
| 营销管理 | coupons, seckills, discounts | 优惠券 / 秒杀 / 折扣 |
| 员工管理 | roles, staff | B 端员工 + 角色 |
| 首页统计 | （无独立表） | 从 orders / products 等聚合查询 |

## 三、用户模块

### 3.1 `users` — 用户主表

| 字段 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| id | BIGINT UNSIGNED | NO | AUTO_INC | 主键 |
| nickname | VARCHAR(20) | NO | | 昵称 |
| phone | VARCHAR(11) | NO | | 手机号（唯一） |
| password | VARCHAR(255) | NO | | 登录密码（bcrypt） |
| register_time | DATETIME | NO | CURRENT_TIMESTAMP | 注册时间 |
| last_login_time | DATETIME | YES | NULL | 最后登录 |
| status | TINYINT | NO | 1 | 1=正常 0=禁用 |
| tags | TINYINT | NO | 2 | 用户标签(互斥): 1=优质客户 2=普通客户 3=恶意用户 |
| total_consumption | DECIMAL(12,2) | NO | 0 | 累计消费（冗余） |
| order_count | INT | NO | 0 | 订单数（冗余） |

**索引**：`UNIQUE(phone)`、`INDEX(status)`、`INDEX(tags)`、`INDEX(register_time)`

> `tags` 为互斥单选字段，后端查询后组装成前端 `['优质客户']` 数组返回。列表页按标签筛选直接 `WHERE tags = ?`，走索引。

> `total_consumption` 与 `order_count` 为冗余字段，订单完成时在事务内同步更新，避免列表页实时聚合。

### 3.2 `user_addresses` — 收货地址

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| id | INT | NO PK | |
| user_id | BIGINT UNSIGNED | NO | FK → users.id |
| name | VARCHAR(20) | NO | 收货人 |
| phone | VARCHAR(11) | NO | |
| address | VARCHAR(200) | NO | 详细地址 |
| is_default | TINYINT | NO | 1=默认 0=非默认 |

**索引**：`INDEX(user_id)`

> 每个 user 只能有一个 is_default=1，通过应用层事务或触发器保证。

### 3.3 `operation_logs` — 用户操作日志

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| id | BIGINT | NO PK | |
| user_id | BIGINT UNSIGNED | NO | 被操作用户 |
| operator | VARCHAR(50) | NO | 操作人（系统 / 客服小王） |
| action | VARCHAR(200) | NO | 动作描述 |
| created_at | DATETIME | NO | CURRENT_TIMESTAMP |

**索引**：`INDEX(user_id, created_at DESC)`

## 十、关键设计决策

### 10.1 冗余字段 vs 实时聚合
- **users.total_consumption / order_count**：冗余存储，订单完成时事务内更新
- **shipment_records.company_code / company_name**：冗余，避免列表页 JOIN
- **orders.user_name / user_phone / recipient_***：快照存储，用户改名不影响历史订单
- **order_items.product_name / spec / price**：快照存储，商品改价不影响历史订单

> 原则：**列表页避免多表 JOIN，详情页可适当 JOIN**。

### 10.2 软删除策略
本设计未显式加 `is_deleted` 字段。原因：
- 当前业务无回收站需求，删除即物理删除
- 员工/用户禁用（status=0）已覆盖"停用但保留"场景

如后续需要回收站功能，可统一加 `deleted_at DATETIME NULL`，并改查询条件为 `WHERE deleted_at IS NULL`。

### 10.3 时间字段命名
- `create_time` / `register_time` / `shipment_time`：业务时间，由应用写入
- `created_at`：通用日志表时间，默认 `CURRENT_TIMESTAMP`

### 10.4 ID 类型选择
- 业务量大的表（users / orders / order_items / logs）：`BIGINT`
- 字典/配置表（categories / tags / roles / logistics_companies）：`INT`
- 前端 mock 中 id 为字符串（如 `'1'`），后端返回 JSON 时数字会自动转字符串，前端兼容无问题

### 10.5 首页统计数据来源
首页 `getCountData` / `getChartData` 等**不建独立表**，从现有表聚合：
- 今日订单数：`SELECT COUNT(*) FROM orders WHERE DATE(create_time) = CURDATE()`
- 今日成交金额：`SELECT SUM(paid_amount) FROM orders WHERE DATE(pay_time) = CURDATE() AND status >= 1`
- 待发货数：`SELECT COUNT(*) FROM orders WHERE status = 1`
- 月度趋势：`GROUP BY DATE_FORMAT(create_time, '%Y-%m')`
- 分类销量：`JOIN order_items GROUP BY category_id`

## 十二、后续扩展建议

1. **权限细化**：当前 roles 表仅做角色枚举，如需按钮级权限（前端 `v-permission` 指令），需新增 `permissions` 表 + `role_permissions` 关联表
2. **优惠券领取记录**：如需追踪哪个用户领了哪张券，新增 `user_coupons` 表（user_id, coupon_id, status, used_order_id）
3. **秒杀订单隔离**：秒杀库存扣减需 Redis 预扣 + 异步落库，避免超卖
4. **操作日志统一**：`operation_logs`（用户）与 `order_logs`（订单）可合并为通用 `audit_logs` 表，加 `target_type` + `target_id` 字段
